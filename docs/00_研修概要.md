## 0.5 研修の全体像（ひとことで）

- 研修生は**設計書を書かない**。要件定義書〜詳細設計書は研修開始前に完成させておき、研修生はそれを読んで**実装だけ**に専念する（5営業日）
- リポジトリには役割の異なる4つのブランチ（`main` / `backend` / `frontend` / `integration`）があり、研修生は基本的に `backend` と `frontend` の2ブランチで作業する（詳細は「9. Git運用の研修的位置づけ」）
- 進め方はDay1-2でバックエンド、Day3-4でフロントエンド、Day5で結合確認という順（詳細は「7. スケジュール」）

## 1. 研修の基本方針

本研修のメインは**実装**である。要件定義書・基本設計書・詳細設計書は、研修生自身が作成するものではなく、研修開始前に**完成させておく確定版ドキュメント**として提供する。研修生（初学者）は、この完成した設計書を読み解きながら、5日間を通じて実装に専念する。

## 2. 研修の目的

- Pythonを用いたWebアプリケーション（バックエンド）実装の基礎を、実際に手を動かして習得する
- フロントエンド／バックエンドの役割分担、およびAPIを介した連携の考え方を体験する
- 完成された要件定義書・設計書を正確に読み解き、そこに書かれた仕様を実装に落とし込む力を養う（実務における「設計書に基づいた実装」の経験）
- Gitを用いたブランチ運用（実装対象ごとのブランチ分割、コミット・プルリクエストの基本）を実践する

## 3. 対象者

未経験〜プログラミング初学者（Pythonの基本文法は学習済みだが、実務でのアプリケーション開発経験はない、または浅い層を想定）

## 4. 研修期間

実装フェーズとして**5営業日**を確保する（詳細は「7. スケジュール」を参照）。要件定義・基本設計・詳細設計はこの5日間には含めず、研修開始前の事前準備として完了させておく。

## 5. 到達目標（ゴール）

研修終了時点で、研修生が以下の状態になっていることを目指す。

1. FastAPIを用いて、シンプルなREST APIを実装できる
2. SQLiteとORM（SQLAlchemy）を用いて、データの永続化処理を実装できる
3. HTML/CSS/JavaScriptを用いて、APIと連携する画面を実装できる
4. 完成済みの要件定義書・設計書を読み、そこに書かれた仕様をコードに落とし込むことができる
5. Gitでブランチを分けて作業し、変更をコミット・プルリクエストとしてまとめられる

## 6. 研修の進め方

### 6.1 事前準備（研修開始前・研修主催者側で実施）

研修生が実装に専念できるよう、以下は研修開始前にすべて完了させておく。

1. **要件定義書の確定**（Cowork上で対話しながら作成・完成）
2. **基本設計書の確定**（画面構成・API一覧・DB設計）
3. **詳細設計書の確定**（API仕様詳細・DB定義・画面遷移・処理フロー）
4. **GitHubリポジトリ・ブランチの作成**（`main`＝完成品、`backend`＝バックエンド実装、`frontend`＝フロントエンド実装、`integration`＝Day5の結合確認用、の4ブランチ）
5. **Claude Code向け実装指示プロンプトの準備**

### 6.2 研修当日（5営業日・実装フェーズ）

研修当日はすべて実装に充てる。研修生は完成済みの設計書を読み解きながら、Claude Code（VSCode）の支援を受けつつ手を動かして実装を進める。詳細なスケジュールは「7. スケジュール」を参照。

## 7. スケジュール（実装5日間）

| Day | 内容 |
|---|---|
| Day1 | 開発環境構築、リポジトリ／設計書の読み合わせ、バックエンド実装①（環境構築・DBモデル・API雛形作成） |
| Day2 | バックエンド実装②（主要API実装：ユーザー登録、スコア登録、ランキング、テトリミノ出現順序APIなど）・単体テスト |

## 9. Git運用の研修的位置づけ

本研修ではリポジトリ内に用途の異なる4つのブランチを用意し、それぞれの実装を通じて役割分担を体験する。研修生が実装するのは`backend`・`frontend`の2ブランチであり、`main`・`integration`は事前準備／Day5の結合確認のために研修主催者側が管理する。

| ブランチ名 | 位置づけ | 研修における役割 |
|---|---|---|
| `main` | 完成品（模範解答）。事前に完成させ、研修中は変更しない | 実装に迷った際の参照用、また研修後の答え合わせに使用する |
| `backend` | バックエンド実装。研修開始時点ではAPI雛形（TODOコメント付き）の状態 | API設計・データ永続化・ビジネスロジックの実装を通じて、バックエンド開発の考え方を学ぶ |
| `frontend` | フロントエンド実装。研修開始時点では画面雛形（TODOコメント付き）の状態 | 画面表示・ユーザー操作・API連携（呼び出し側）の実装を通じて、フロントエンド開発の考え方を学ぶ |
| `integration` | 結合確認用。事前準備では空（ディレクトリのみ）の状態で用意 | Day5に研修生自身の`backend`・`frontend`ブランチをマージし、結合動作を確認する土台として使う |

具体的なブランチ保護設定、マージ方針などの技術的な取り決めは「要件定義書」および「基本設計書」に定める。
